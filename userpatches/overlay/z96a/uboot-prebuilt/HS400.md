# Z96A eMMC HS400 — experiment log & full rollback

Status: **experimental / not for daily use**. Linux HS400 already failed once; current tree stays on HS200. This note covers a **U-Boot-only** HW probe.

## What we already know

| Fact | Detail |
|------|--------|
| Card (SPeMMC 29.1 GiB) | EXT_CSD: **HS400 @200 MHz 1.8 V** + **Enhanced Strobe** |
| Linux (edge 7.2) before | **HS200 @200 MHz**, seq read ~**153 MB/s** |
| Linux + `mmc-hs400-1_8v` + ES | Kernel booted to **initramfs**, **no `/dev/mmcblk*`** → unbootable |
| Linux tree now | `&sdhci`: HS200 only; `&sfc` disabled (pin conflict was `gpio1-23` / eMMC) |
| Stock U-Boot v2026.07 | DT had hs400 props, but **`CONFIG_MMC_HS400_SUPPORT` was off** → always HS200 |

So: **particle supports HS400**; **Linux path broke**; **U-Boot never actually negotiated HS400** until this test build.

## Goal of this U-Boot build

Prove **controller + board wiring** can do HS400 under U-Boot:

- Enable `CONFIG_MMC_HS400_SUPPORT=y`
- Keep `CONFIG_MMC_HS400_ES_SUPPORT` **off**
- DT: keep `mmc-hs400-1_8v`, **drop** `mmc-hs400-enhanced-strobe` for first probe

If `mmc info` shows HS400 and `mmc read` is stable → hardware OK → Linux is a driver/tuning problem.  
If U-Boot also fails → don’t chase Linux HS400 yet.

## Serial checks at U-Boot `=>`

```text
mmc list
mmc dev 0
mmc info
mmc read 0x10000000 0 0x8000
```

| Result | Meaning |
|--------|---------|
| Mode **HS400**, clock ~200 MHz, read OK | Hardware path works |
| Still **HS200** | Kconfig/DT not applied, or driver refused HS400 |
| No card / errors | Same class of failure as Linux — stop, roll back U-Boot |
