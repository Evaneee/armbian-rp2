# Z96A 笔记本蓝牙整改总结报告

## 一、结论

这次整改解决了三个蓝牙问题，并顺带做了一项安全优化：

1. 经典蓝牙设备现在可以免密码配对，不用再输 PIN 码。
2. 蓝牙耳机连上后声音自动切到耳机，断开后自动回到板载扬声器。
3. 耳机播放卡顿、断声的原因已经查明，是 GNOME 蓝牙设置页面开着时持续搜索设备、抢占空口。目前的解决办法是听歌时关掉这个页面。
4. 板子默认不再被周围设备搜到，只在打开蓝牙设置页面配对时才可被发现。

以上都已在板子上实测验证。提交：`d6a1eafaa`、`2a90de1fe`（rp3576-work）。

**测试环境**

| 项目 | 内容 |
|---|---|
| 主板 | Z96A（RK3568） |
| 蓝牙芯片 | RTL8821CS（Wi-Fi/蓝牙二合一），UART H5 协议，1.5 Mbps，固件 `0xaa8a930d` |
| 软件 | BlueZ 5.72、PipeWire 1.0.5、WirePlumber 0.4.17、内核 7.3.0-rc6-edge |
| 测试设备 | 荣耀亲选耳夹耳机 2 Pro（A2DP/HFP）、手机 |

## 二、问题一：经典蓝牙只能 PIN 码配对，无法免密配对

### 现象
耳机、手机这类经典蓝牙（BR/EDR）设备配对时要求输入 PIN 码，或者直接配不上。免密配对（Just Works）一直不可用。

### 原因
- 免密配对依赖 SSP（Secure Simple Pairing，安全简易配对）。以前的结论是"这块固件开不了 SSP"，所以启动脚本强制关掉了 SSP，经典蓝牙只能退回旧式 PIN 码配对。
- 重新分析当时的报错发现，失败的 HCI 命令是 `0x0c7a`，返回状态 `0x03`（硬件失败）。`0x0c7a` 不是写 SSP 的命令（那个是 `0x0c56`），而是 **Write Secure Connections Host Support**。
- BlueZ 默认会打开 SSP 的扩展功能"安全连接"（Secure Connections，SC）。内核每次打开 SSP 后，会紧接着写这条 SC 命令，而 RTL8821CS 当前固件不支持 SC，于是整个上电失败。
- 所以真正有问题的是 SC，SSP 本身是好的。

### 修改
1. **启动顺序**（`overlay/z96a/etc/z96a/z96a-bt`）：断电 → **开 SSP** → **关 SC** → 开 LE → 可绑定 → 上电。
   - 顺序很关键：在支持 SC 的控制器上，内核要求先开 SSP 才能关 SC，否则 `sc off` 会被拒绝（返回 `0x0b Rejected`）。
   - 保留兜底：如果按这个顺序还是上不了电，脚本自动退回"关 SSP"的旧方案，保证蓝牙至少能用。
2. **BlueZ 配置**（`bluetooth.inc`）：`/etc/bluetooth/main.conf` 加上 `SecureConnections=off`，防止 bluetoothd 启动时又把 SC 打开。
3. **清理**：删掉了 `overlay/z96a/bin/z96a-bt-post`。它和 `etc/z96a/z96a-bt` 内容相同，但构建时从来没被安装过；真正生效的是后者，并以符号链接 `/usr/local/bin/z96a-bt-post` 的形式被调用。

### 验证
- 控制器状态变为"已上电、SSP 开、SC 关"，`btmon` 抓包显示 Write Simple Pairing Mode 返回成功。
- 模拟 GNOME 里开关蓝牙，连续断电再上电 3 次都成功。以前一开 SSP，GNOME 的蓝牙开关就会失效。
- 重启 bluetoothd 和 `z96a-bt-ready` 后，日志显示 `sc off + ssp on + power on`，最终状态正确。
- 实际配对的抓包里两次都是 SSP 配对，没有出现任何 PIN 码请求：
  - 手机：数字比较方式，两边显示同一组 6 位数字，生成认证密钥（Authenticated，P-192）。
  - 耳机：Just Works 方式，直接配对，生成非认证密钥（Unauthenticated，P-192）。

## 三、问题二：耳机连上后声音仍然从板载扬声器发出

### 现象
耳机已经配对并连接，PipeWire 里也出现了耳机这个输出设备，但默认输出仍是 RK817 板载扬声器，Chromium 的声音也从扬声器出来。

### 原因
有两处问题叠加：
1. **登录脚本锁定了默认输出**：`z96a-set-pipewire-sink` 每次登录都执行 `pactl set-default-sink RK817`。WirePlumber 会把它当成用户手动选定的默认输出（`default.configured.audio.sink`）记下来，之后只要扬声器存在，耳机连上也不会切换。
2. **扬声器优先级更高**：WirePlumber 规则给 RK817 设的优先级（`priority.session`）是 2000，比蓝牙设备默认的优先级高。即使没有锁定，自动挑选时也会选扬声器。

### 修改
1. 新增 `overlay/z96a/etc/wireplumber/bluetooth.lua.d/51-z96a-bt-priority.lua`，把所有蓝牙输出（`bluez_output.*`）的优先级设为 3000。现在的顺序是：蓝牙 3000 > RK817 扬声器 2000 > HDMI 100。
2. `z96a-set-pipewire-sink` 只负责取消扬声器静音、设置音量，不再执行 `set-default-sink`。
3. `sound.inc` 加上新规则文件的安装步骤。

### 验证

| 操作 | 默认输出 |
|---|---|
| 耳机连上 | 耳机（`bluez_output.*`，优先级 3000） |
| 耳机断开 | RK817 板载扬声器 |
| 耳机重连 | 耳机 |

Chromium 没有被绑定到某个输出上，正在播放的声音会跟着默认输出自动切换。

## 四、问题三：耳机播放 Chromium 视频时卡顿、断声

### 现象
用耳机听 Chromium 视频时多次断声和卡顿，开头 20 秒最明显。

### 排查过程

| 怀疑方向 | 检查结果 | 结论 |
|---|---|---|
| PipeWire 欠载 | 播放全程错误计数为 0，耳机和 Chromium 两个节点负载都不到 1% | 排除 |
| CPU 或温度 | CPU 一直在 2208 MHz，温度 47–57 ℃ | 排除 |
| Wi-Fi 干扰 | Wi-Fi 在 5 GHz，省电已关；关掉 Wi-Fi 后停顿反而略多（9 次 vs 6 次） | 排除 |
| 信号强度 | RSSI 约 -52，耳机支持 EDR 2 Mbps 和 5 时隙包 | 排除 |
| 串口带宽 | H5 协议 1.5 Mbps，A2DP 只需要约 200 kbps | 排除 |
| **设备搜索** | 播放期间一直在做经典蓝牙查询（Inquiry）和 LE 扫描 | **确认是原因** |

### 原因
- 板子上开着 GNOME 设置的蓝牙页面（`gnome-control-center bluetooth`），`bluetoothctl` 显示 `Discovering: yes`。这个页面只要开着，就会持续搜索周围设备，每 16 秒一个循环：约 10.24 秒的经典蓝牙查询，加约 5.7 秒的 LE 扫描。
- 经典蓝牙查询要在 32 个频点上反复跳频收发，会占掉大部分空口时间。A2DP 音频只能在空隙里发，控制器只有 8 个包的缓冲（`ACL MTU 1021:8`），很快就会被塞满，耳机端的缓冲随之被饿空，就会卡顿、断声。
- 抓包时间对齐后的对应关系：

| 时间段（秒） | 蓝牙在做什么 | 音频发送情况 |
|---|---|---|
| 13.1 – 23.3 | 经典蓝牙查询 | 缓冲持续塞满，出现大量 60–119 ms 停顿 |
| 23.3 – 29.1 | 只做 LE 扫描 | 基本顺畅 |
| 29.1 – 39.3 | 经典蓝牙查询 | 又被塞满 |
| ……之后每 16 秒重复 | | |

### 处理
- **使用上的解决办法**：听歌时关掉 GNOME 设置里的蓝牙页面，或者关掉整个设置窗口，只在配对新设备时打开。这是 Linux GNOME 的通病，不是本板特有的问题。
- **配套优化**：见第五节。

## 五、优化：默认不可被发现

### 原来的情况
`z96a-bt` 每次开机都执行 `btmgmt discov on`，而且没有超时。板子开机 25 分钟后仍然可被发现，周围任何设备都能搜到它并发起配对请求。

### 修改
`z96a-bt` 启动时改为主动关闭"可被发现"（`discov off`）。"可配对"和"可连接"保持打开。打开 GNOME 的蓝牙设置页面时，GNOME 会临时让板子可被发现，关掉页面后自动恢复。这和普通 Ubuntu 笔记本的行为一致。

### 验证
重启蓝牙启动服务后，状态为 `Discoverable: no`、`Pairable: yes`、可连接，耳机保持连接不受影响。

### 影响
- 已配对的设备照常回连，不受影响。
- 用手机主动配对板子时，需要先在板子上打开蓝牙设置页面。

## 六、相关修复：扬声器路由服务失败

提交在 `4590d058c`。

- **现象**：开机后 `z96a-speaker-route.service` 失败。
- **原因**：摄像头上电修好以后，它的 USB 麦克风占了声卡 0，RK817 变成了声卡 2。而这个服务和 `asound.conf` 都把声卡编号写死成了 0。
- **修改**：两者都改为按声卡名 `RK817` 访问，不再依赖编号。

## 八、使用说明

- **配对新设备**：在板子上打开 GNOME 设置的蓝牙页面，然后在手机或耳机上发起配对。耳机一般会直接连上，手机会显示 6 位数字让你确认。配对完关掉页面。
- **听歌**：确认 GNOME 蓝牙设置页面已经关掉，否则持续的设备搜索会导致卡顿。
- **切换输出**：耳机连上自动切换，断开自动回到扬声器。如果在 GNOME 声音设置里手动选了某个输出，WirePlumber 会记住这个选择，之后以手动选择为准。

## 九、遗留事项

1. **SC 不可用**：固件不支持安全连接（SC），所以经典蓝牙配对用的是 P-192 密钥，而不是更强的 P-256。对日常使用的耳机、手机没有影响。如果以后有更新的 RTL8821CS 固件，可以再测试 SC。
2. **单天线共用**：RTL8821CS 的 Wi-Fi 和蓝牙共用射频。测试中 Wi-Fi 工作在 5 GHz，没有观察到干扰。如果改连 2.4 GHz 的 Wi-Fi，耳机可能会受影响，到时需要单独评估。
3. **设置页面开着会卡**：这是 GNOME 本身的行为，目前只能靠使用习惯规避。如果以后要从系统层面处理，可以考虑在 A2DP 播放期间暂停设备搜索，但这需要改 BlueZ 或另写守护脚本。
